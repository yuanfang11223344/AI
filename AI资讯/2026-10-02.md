## 🧠 大模型与 LLM 技术解读

1. 🔥 GPT-6 family guide
   - 背景：OpenAI 在 DevDay 后需要把 GPT-6 能力转译成开发者可执行的模型选择策略。
   - 问题：企业应用常在 latency、cost、reasoning depth、tool use 与 safety 之间摇摆。
   - 方法：官方 guide 以模型家族视角解释不同 GPT-6 型号的使用场景，帮助开发者按任务而非品牌名选型。
   - 效果：这是实践指南，不是独立 benchmark；效果需看实际调用成本与任务成功率。[来源](https://openai.com/index/practical-guide-building-gpt-6/)
2. 🔥 Gemini 4 Argon
   - 背景：Google 把 Argon 用作重新进入 frontier 模型竞争的关键发布。
   - 问题：防御性 cyber、长文档法律/金融、代码迁移等任务需要更长上下文和多步推理。
   - 方法：1M context、面向 long-horizon workflows 的 reasoning，并通过 Fairwind Program 控制早期访问。
   - 效果：官方称达到 frontier performance；第三方 Artificial Analysis 已收录但可公开复核的细节有限。[来源](https://artificialanalysis.ai/models/gemini-4-argon)
3. ⭐ OpenAI Dots
   - 背景：Agent 入口从 API 和开发者框架进入普通 ChatGPT 用户界面。
   - 问题：用户不想手动轮询待办、Slack、文档和财务系统。
   - 方法：dot 常驻观察任务上下文，准备行动并在关键步骤等待用户批准。
   - 效果：官方示例说明了自动发现/准备任务的方向；暂无独立评测。[来源](https://openai.com/index/introducing-dots/)
4. ⭐ Claude Opus 5.5
   - 背景：Anthropic 面向 long-running agentic coding 推出更低成本 Opus。
   - 问题：长上下文和多工具调用成本高，且模型行为变更可能影响已有应用。
   - 方法：1M context、adaptive thinking always on，并调整 forced tool use、thinking block 等行为。
   - 效果：官方标称价格 $4/$20 per MTok，典型成本低于 Opus 5；实际迁移需回归测试。[来源](https://platform.claude.com/docs/en/models/opus-5-5/overview)
5. 📌 ThinkingBox
   - 背景：Agent benchmark 从“答对题”转向“是否改变了有状态业务环境”。
   - 问题：代理声称完成任务，但数据库、订单或票据状态未必一致。
   - 方法：ThinkingBox 使用可执行环境、MCP servers、Typesense 和 evaluator 检查 episode 结果。
   - 效果：公开环境可复现 benchmark 流程；benchmark 任务为 synthetic reconstruction，不能等同真实客户数据。[来源](https://huggingface.co/blog/microsoft/thinkingbox)
