## 🧠 大模型与 LLM 技术解读

### 1. 🔥 GPT-5.6：用 retained reasoning、compaction 和 programmatic tool calling 改变 agent 架构

- **背景：** Frontier model 竞争正在从单次问答 benchmark 转向长程 agent 的可持续成本、上下文连续性和工具编排能力。[来源](https://openai.com/index/builders-guide-to-gpt-5-6/)
- **问题：** 长程 agent 容易重复构建上下文、把确定性过滤/聚合塞进模型上下文，并在多工具并行任务中浪费 token 和延迟。
- **方法：** OpenAI 在 Responses API 中强调 retained reasoning、native compaction、native multi-agent orchestration 与 programmatic tool calling：把已完成推理跨 turn 复用，把长对话压缩，把可并行 workstream 分给 subagents，把确定性工具结果处理放到代码中。
- **效果：** 官方称 ARC-AGI-3 harness 中 GPT-5.6 Sol 在启用 retained reasoning 与 compaction 后从 13.3% 提升到 38.3%，并使用约 6x 更少输出 token；这是官方 harness 结果，仍需独立复测。

### 2. 🔥 GPT-5.6 Sol Ultrafast：用 Cerebras serving 把 frontier intelligence 推向实时业务

- **背景：** 过去低延迟常意味着使用小模型或牺牲能力；语音客服、incident response、金融研究等场景需要模型在对话或故障窗口内完成多步判断。[来源](https://openai.com/index/previewing-ultrafast/)
- **问题：** Agent 延迟不仅来自 tokens/s，也来自模型是否能用更少轮次完成正确工具调用和判断。
- **方法：** OpenAI preview 的 Ultrafast service tier 在 Cerebras 上运行 GPT-5.6 Sol，面向 API 场景，官方称最高 750 output tokens/s、最高 14x faster than Standard processing。
- **效果：** 官方给出早期客户场景与内部 incident response 用例；目前仍是 preview，暂无公开独立吞吐/质量评测。

### 3. 🔥 Nemotron 3.5 Lightning：30B total / 3B active MoE 服务高频 agent execution

- **背景：** always-on agents 的主体流量常是 tool call、结果校验、格式化、routine coding，而不是每步都需要 frontier reasoning。[来源](https://developer.nvidia.com/blog/nvidia-nemotron-3-5-lightning-delivers-fast-accurate-specialized-task-execution-for-long-running-agents/)
- **问题：** Dense frontier model 用于高频执行会带来过高成本和排队延迟；普通小模型又可能在工具调用准确性上不足。
- **方法：** NVIDIA 称 Nemotron 3.5 Lightning 是 customizable open 30B MoE、3B active parameters，包含 multi-token prediction/speculative decoding，并面向 agent harness 训练；NeMo Switchyard 负责把 plan route to frontier、execution route to Lightning。
- **效果：** 官方称其在同类小 open model 中达到 accuracy-speed Pareto frontier，并在 PinchBench 上以相近准确率比 Qwen3.6 35B 完成 10,000 tasks 快 30%；该效果来自 NVIDIA/相关榜单，企业仍需内部 eval。

### 4. ⭐ Claude Sonnet 5：把 agentic Sonnet 作为 Opus/Fable 之下的执行层

- **背景：** 企业 coding agent 与业务 agent 需要长期运行、检查输出、遵守项目约定，同时控制每百万 token 成本。[来源](https://www.anthropic.com/news/claude-sonnet-5)
- **问题：** 旗舰模型能力强但成本高；较小模型如果不能自主推进多步任务，就无法承担执行层。
- **方法：** Anthropic 将 Sonnet 5 描述为更 agentic 的 Sonnet，强调 plan、tool use、browser/terminal autonomous work，并把 8 月 10 日更新后的价格固定在 $2/MTok input、$10/MTok output。
- **效果：** 官方早期客户反馈强调 coding、Salesforce 自动化、bug reproduction/fix 等长程工作；暂无独立评测，需按真实 repo 和工具权限复测。

### 5. ⭐ AI agent 安全：MCP/skills 供应链成为模型能力之外的关键面

- **背景：** Agent 不再只调用内置工具，而是会搜索、安装、启用第三方 MCP servers、skills 和 GitHub repo。[来源](https://www.pcgamer.com/software/ai/welcome-to-the-internet-in-2026-where-ai-agents-are-both-victim-and-attacker-in-malware-wars/)
- **问题：** 恶意 repo 可通过 README、tool schema 或安装脚本诱导 agent 执行不安全操作；agent 自主性越高，供应链攻击越容易被放大。
- **方法：** 公开讨论中的防线包括 allowlist、签名/来源校验、最小权限、沙箱、安装前人工 approval、工具调用审计和 MCP gateway/registry。
- **效果：** 目前多为安全研究与媒体披露；暂无统一行业 benchmark，但对企业 agent 落地属于必须优先处理的工程风险。
