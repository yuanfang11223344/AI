## 🧠 大模型与 LLM 技术解读

### 1. 🔥 dsh-superagent：将长期协作拆成获授权的工作项
- **背景**：编码 Agent 从单轮交互进入团队持续协作，容易产生状态混乱和过多通知。
- **问题**：如何接收事件、限定行动授权，并让人找到真正需要处理的事项？
- **方法**：研究原型绑定一个 GitHub 仓库，监听 GitHub 与可选的飞书事件；获准请求触发工作项，在独立会话和目录中执行，通过原对话回传结果，面板展示需要人工介入的任务。仅在请求或团队规则允许时行动。
- **效果**：仓库提供实现和文档，暂无独立评测；未给出可核验的长期任务成功率或成本对照。公开版不等同内部版，不能把设计文章中的未来能力全部算作已实现。
- **来源**：[DeepSeek 团队仓库](https://github.com/deepseek-ai/dsh-superagent-prototype)

### 2. 🔥 CORAL：主动保存检查点，再清理长任务上下文
- **背景**：长流程 Agent 的上下文会混入无关信息，影响规划与推理。
- **问题**：一直追加历史会消耗输入 token，也可能稀释真正重要的事实。
- **方法**：提供可由 Agent 调用的工作记忆工具，保存任务进度与已验证事实，再重置上下文开启新 episode；通过 Multi-episode Agentic Reinforced Policy Optimization 训练检查点能力。
- **效果**：作者报告 8B 模型在 GAIA 达到 42.8% 平均准确率，相对 ReAct 输入 token 减少约 6—7 倍；这是特定实验对照，不能等同总费用或墙钟时间同幅下降。暂无独立评测。论文指向的代码地址本次返回 404，未验证可运行性。
- **来源**：[Don't Lose the Thread](https://arxiv.org/abs/2610.40350)

### 3. ⭐ Glance：复用生成器与 prefill 做检索重排
- **背景**：RAG 常同时驻留独立 reranker 和生成模型，重复处理候选段落。
- **问题**：如何减少模型驻留和逐候选 prefill，同时保留检索质量？
- **方法**：在生成器上增加轻量 decision adapter 与 pointer head，候选段落共享一次 prefill，从缓存分支出短 relevance probe，为各段落打分。
- **效果**：作者在单个 9B backbone 上报告每种 decision skill 约增加 0.1 GiB 内存；300 道 HotpotQA 中，相同生成器下答案 F1 比 cross-encoder 所选上下文高 0.045。暂无独立评测；评估仅覆盖两个检索数据集、一个 QA 数据集及一个 backbone 家族，尚不能外推到所有线上 RAG。
- **来源**：[Glance](https://arxiv.org/abs/2610.40454)

### 4. ⭐ rTaste：会提出实验，不等于会挑选最值得做的实验
- **背景**：科研 Agent 的能力常按提案文本质量判断，缺少真正执行后的对照。
- **问题**：Agent 的排序和成功率预测，是否比简单基线更有价值？
- **方法**：让六个模型基于七篇 NLP 论文提出、预测并排序最小可行实验；独立执行器尝试全部实验，包括排在最后的方案，再由三个模型审计结果。
- **效果**：415 项实验中，194 项被审计为合理、有价值且新颖，73 项进一步被认为超越种子论文且不显然；排序未显示优于直接选第一个生成的实验，团队成本更高但无清晰总体质量收益。暂无独立评测；模型审计并不等于专家共识。
- **来源**：[rTaste](https://arxiv.org/abs/2610.40488)

### 5. ⭐ TOME-Math：保留教材结构，而非只抽取问答对
- **背景**：数学训练材料常被压平成独立题目与答案，丢失章节和证明依赖。
- **问题**：能否把教材组织结构变成可扩展的证明监督？
- **方法**：从 2,118 本教材构建约 38 万条记录，保留章节顺序、命题—证明关系、依赖引用与来源，并研究课程学习和数据规模效应。
- **效果**：作者报告完整数据规模下，留出评测与公共基准的非加权均分比基础模型增加 16.7 个百分点。暂无独立评测；摘要称将发布语料，不据此认定数据已经开放下载，也不能把均分变化当成每项任务增益。
- **来源**：[Scaling Mathematical Proof Supervision from Structured Textbooks](https://arxiv.org/abs/2610.40394)

### 6. ⭐ Rethinking Pre-pretraining：合成预热必须在相同算力下比较
- **背景**：部分研究先用合成数据预热，再进行自然语言预训练。
- **问题**：增益究竟来自合成课程，还是额外计算预算与初始化差异？
- **方法**：控制算力，比较 k-Dyck、NCA、声明式引用语料和代码四类课程，覆盖数据受限、不受限及高 token/参数比训练，并检查初始化与遗忘。
- **效果**：作者在其等算力实验中未发现 PPT 优于纯自然语言训练；额外算力带来的小数据增益在自然语言数据达到 1B token 时消失。暂无独立评测；结论限于所测规模与课程，不意味着所有合成训练数据无用。
- **来源**：[Rethinking Pre-pretraining](https://arxiv.org/abs/2610.40051)
