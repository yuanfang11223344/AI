## 🧠 大模型与 LLM 技术解读

### 1. 前沿模型的外部评估：METR 式访问治理成为技术发布的一部分

- **背景**：能调用代码、浏览器和企业工具的 Agent，使传统静态 benchmark 难以覆盖真实自主性与权限边界。
- **问题**：评估机构需要足够访问权才能检查高风险能力，但模型厂商又必须管理敏感权重、数据和内部系统的暴露面。
- **方法**：Anthropic 的 newsroom 表示正向非营利评估机构 METR 提供接近员工级的系统访问，并探讨与其他机构的合作；这是评估流程设计，不是新模型架构。
- **效果**：它增加了可被外部审阅的入口，但尚未形成公开、可横向比较的安全分数；**暂无独立评测结论**，不能据此推断任一模型安全等级。[来源](https://www.anthropic.com/news?subjects=announcements)

### 2. 大规模行业 Agent：从聊天界面进入跨系统决策链

- **背景**：企业正尝试把 LLM 从单点问答接到计划、调度和数据检索流程，油气等高资产行业尤其重视跨域数据连接。
- **问题**：跨系统 Agent 面临数据孤岛、工具权限、可追溯决策和人工接管等难题；自然语言正确性不能替代运营正确性。
- **方法**：ADNOC 称拟以 OpenAI GPT 模型连接其多年油田数据、储层和地面设施数据，用于 field master planning，并由多个 Agent 衡量商业与运营影响。
- **效果**：公告称可把复杂开发计划准备与优化从“数月”缩短到“数小时”；这是合作方主张，未公布任务集、基线或独立审计，**暂无独立评测**。[来源](https://www.adnoc.ae/media-center/news/2026/11/ADNOC-Signs-Landmark-Partnership-Agreement-with-OpenAI)

### 3. 使用政策版本化：模型能力升级必须与可执行控制同步

- **背景**：模型的工具使用和专业领域能力提升后，安全边界不能只由用户提示词临时约束。
- **问题**：组织需要让允许用途、禁止用途、账户治理和事后审计跟随模型/产品版本更新，避免旧流程继续承载新的能力面。
- **方法**：Anthropic 公布 2026 Usage Policy 更新并说明于 11 月 12 日生效；它属于治理层规范，而非训练算法或模型性能发布。
- **效果**：可为采购和部署提供明确版本锚点，但政策文本本身不证明执行效果或防滥用能力，**暂无独立评测**。[来源](https://www.anthropic.com/news/2026-usage-policy-update)

### 4. 以资本建设推理/训练供给：模型能力路线受系统约束

- **背景**：前沿 LLM 的训练与在线推理都受供电、GPU、网络与融资能力制约，模型公司和基础设施公司正共同前置锁定资源。
- **问题**：在需求与供应都不确定时，如何建设长期算力而不过度把规划目标当成交付事实。
- **方法**：OpenAI/NVIDIA 的公开材料提出至少 10GW 系统部署意向，并称双方会共同优化模型/基础设施软件与硬件软件路线；其核心是系统协同与供给规划，不是模型权重更新。
- **效果**：首个 1GW 的目标时间为 2026 年下半年；该时间表为前瞻性陈述，未构成实际上线或推理成本的独立证据，**暂无独立评测**。[来源](https://openai.com/index/openai-nvidia-systems-partnership/)

### 5. Agent 科学任务评测：须同时测结果、工具轨迹和人工监督

- **背景**：科研 Agent 开始覆盖文献检索、实验规划和软件/仪器交互，单个问答基准难以代表实际实验室环境。
- **问题**：任务得分不等价于过程安全、可复现或符合 SOP；失败恢复和权限升级也需纳入评估。
- **方法**：OpenAI 的公开文章讨论如何度量 Agent 处理日常 wet-lab 科学任务，可将任务分解、工具轨迹、监督节点与失败模式一并作为证据。
- **效果**：该框架为能力验证提供了任务化观察入口，但不是通用部署认证；未给出可替代现场验证的独立结论，**暂无独立评测**。[来源](https://openai.com/index/measuring-how-ai-agents-handle-wet-lab-science/)

## 🖥️ 芯片与互连

- 🔥 **CPO 继续走向“光引擎 + 224G SerDes + chiplet”协同**：Lightmatter 与 Synopsys 计划把 3nm 224G SerDes、UCIe IP 结合到 Passage 3D CPO 平台。该材料描述联合开发路线，非量产或端到端能效的独立证明。[Lightmatter 公告](https://lightmatter.co/press-release/lightmatter-collaborates-with-synopsys-to-integrate-advanced-interface-ip-with-its-passage-co-packaged-optics-platform/)

- ⭐ **从 1.6T 到 3.2T，路由选择需要按距离而非只按每 lane 速率**：Qualcomm 的数据中心资料并列 die-to-die、PAM4 electrical/optical SerDes、CPO/NPO、AEC 与 coherent-lite，提示毫米到公里级互连的封装、链路预算与可维护性必须共同权衡。[Qualcomm Investor Day 材料](https://www.qualcomm.com/content/dam/qcomm-martech/dm-assets/documents/Investor-Day-2026_TPialis_Data-Center.pdf)
- 📌 **448G PAM4 的 CPO 封装仍需区分仿真与测量**：ECTC 论文描述 PIC-in-mold interposer 架构，并给出 448Gbps PAM4 眼图的 channel simulation；其 CPWG 测试结构的测量和系统眼图仿真不能混为整机实测。[IEEE 论文页](https://ieeexplore.ieee.org/document/11561379/)
- 📌 **400G/λ 硅光器件提供速率上限参照，不等于可量产交换机**：论文报告硅微环的 200Gb/s NRZ、360Gb/s PAM4、400Gb/s PAM6 开眼图；应把它理解为器件级实验结果。[arXiv:2509.01555](https://arxiv.org/abs/2509.01555)
