## 🧠 大模型与 LLM 技术解读

1. 🔥 GPT-5.6 Sol 与 Luna 的产品化推理控制
   - 背景：OpenAI 正在把最新 GPT-5.6 系列同时放入 ChatGPT、Codex 和 API 场景，前沿模型能力与日常访问层开始合并。
   - 问题：用户既需要更强推理，又需要低门槛、低摩擦访问；单一固定推理预算容易造成成本浪费或回答深度不足。
   - 方法：OpenAI 在 ChatGPT 中提供更可靠的 GPT-5.6 Sol，并引入控制思考强度的 slider；免费层使用 GPT-5.6 Luna，并用 Think button 触发更长推理。
   - 效果：官方声称回答更聚焦、事实更可靠、免费用户可无限文本聊天；当前主要依据为 OpenAI 发布声明，暂无独立评测。
   - 来源链接：[OpenAI ChatGPT 更新](https://openai.com/index/improving-gpt-5-6-sol-in-chatgpt/)、[GPT-5.6 Sol 预览](https://openai.com/index/previewing-gpt-5-6-sol/)
2. 🔥 Claude Sonnet 5 的能力/价格重新定位
   - 背景：企业 LLM 部署进入代码 Agent、知识工作、API 批量调用并行增长阶段，模型单价直接影响生产环境替换意愿。
   - 问题：如果高级模型价格波动大，企业难以为 Agent 编排、长上下文任务和 coding workflow 做稳定成本模型。
   - 方法：Anthropic 将 Sonnet 5 的 $2 input / $10 output per million tokens 价格固定为长期价，弱化原先 9 月涨价预期。
   - 效果：官方定价变化可验证，但性能/成本优势仍需用户在自身工作负载上评测；暂无独立评测。
   - 来源链接：[Anthropic Claude Sonnet 5](https://www.anthropic.com/news/claude-sonnet-5)
3. ⭐ NeMo Switchyard 的多模型路由
   - 背景：长时间 Agent 往往包含规划、工具调用、验证、子任务委派等多种 token 密集型步骤，不一定每一步都需要 frontier model。
   - 问题：全程调用最强模型会放大成本和延迟；固定小模型又可能在复杂节点失败。
   - 方法：NeMo Switchyard 提供 provider-agnostic SDK，并包含 tuning-free 与 tunable routers，例如 LLM classifier、stage router、escalation router，根据任务复杂度、成本与基础设施信号选择模型。
   - 效果：NVIDIA 声称可平衡性能、成本与效率；目前主要是官方技术博客和开源发布说明，暂无独立评测。
   - 来源链接：[NVIDIA NeMo Switchyard](https://developer.nvidia.com/blog/route-ai-agent-workloads-across-models-with-nvidia-nemo-switchyard/)
4. ⭐ Nemotron 3.5 Lightning 面向长运行 Agent 的专用执行模型
   - 背景：Agent 系统中大量时间消耗在高频执行动作，而不是少量复杂推理节点。
   - 问题：用大模型处理所有工具调用、结果验证和 delegation 会导致单位任务成本过高。
   - 方法：NVIDIA 将 Nemotron 3.5 Lightning 作为 fast specialized model，配合 NeMo Switchyard 与其他模型共同部署，并开放权重、数据和 recipes 以便定制。
   - 效果：官方称适合长运行 Agent 的快速、准确专用任务执行；实际跨业务 workload 表现仍需独立 benchmark。
   - 来源链接：[NVIDIA Nemotron 3.5 Lightning](https://developer.nvidia.com/blog/nvidia-nemotron-3-5-lightning-delivers-fast-accurate-specialized-task-execution-for-long-running-agents/)
5. ⭐ LLM Agent 安全从单模型红队转向系统级审计
   - 背景：OpenAI/Hugging Face 7 月安全事件披露后，社区对 frontier agent 的越权行为、沙箱边界和平台联动风险持续讨论。
   - 问题：传统模型评测很难覆盖 Agent 在工具、网络、权限和第三方平台交互中的组合风险。
   - 方法：Hugging Face 以技术时间线复盘 incident，并把关注点放到 agent harness、权限边界、日志与事后取证；Black Hat AI Summit 也把 AI 与 cybersecurity 放入单日峰会议程。
   - 效果：事件披露和会议议程可验证，但针对跨平台 Agent 的标准化安全 benchmark 仍不成熟。
   - 来源链接：[Hugging Face 技术时间线](https://huggingface.co/blog)、[Black Hat AI Summit](https://blackhat.com/us-26/ai-summit.html)
