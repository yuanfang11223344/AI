## 🧠 大模型与 LLM 技术解读

1. 🔥 **GPT-5.6 的低成本 Agent 分层路线**
   - 背景：企业 Agent 正从单次问答转向多步工作流，瓶颈从“能不能做”变成“能不能按成本大规模运行”。
   - 问题：高阶模型全程执行会推高 token、延迟和推理成本；低价模型如果没有工具调用和上下文管理，又难以承担真实任务。
   - 方法：OpenAI 将 GPT-5.6 系列拆成 Luna/Terra/Sol 三档：Sol 做高不确定性规划与复杂判断，Terra 覆盖日常工作，Luna 承担高吞吐、工具调用、测试运行、结构化执行等后台 Agent 步骤；系统侧依赖更好的 routing、production kernel、context management 与 prompt cache reuse。
   - 效果：OpenAI 公开称 Luna 降价 80%，Terra 降价 20%，Sol Fast mode 可在智能不变下达到 Standard 的最高 2.5 倍速度；客户案例仍主要是官方与合作伙伴数据，暂无独立评测。[来源](https://openai.com/index/advancing-the-price-performance-frontier-with-gpt-5-6/)

2. 🔥 **GPT-Live 的 full-duplex voice architecture**
   - 背景：语音助手正从 turn-based speech-to-text/text-to-speech pipeline 走向原生实时对话。
   - 问题：传统 turn detector 需要判断用户何时说完，容易过早打断或延迟响应；工具调用和长会话 context compaction 又会阻塞实时音频路径。
   - 方法：OpenAI 的 GPT-Live 让 voice model 同时听和说，把 audio media path 与 tool/deep reasoning path 分离；音频使用 WebRTC 与 Go media frontend，长会话通过 model instance handoff 与动态 context compaction 保持 stateful inference。
   - 效果：OpenAI 称新系统的 p95 frame delivery 可达到旧系统 p50 水平，并支持在语音路径不中断的情况下异步委托 GPT-5.5 等 frontier model；暂无第三方低延迟评测。[来源](https://openai.com/index/continuous-voice-interaction-with-gpt-live/)

3. ⭐ **Claude Opus 5 的“接近 Fable 5、成本减半”定位**
   - 背景：Anthropic 今年的 Claude 系列重点放在 coding、knowledge work、scientific research 与安全能力的组合。
   - 问题：最高能力模型通常成本高、吞吐低，生产环境需要在质量、价格和安全任务能力之间折中。
   - 方法：Anthropic 将 Opus 5 定位为高能力但更经济的旗舰模型，并在 release notes 中强调 coding 与知识工作评测表现；它仍承认在 cybersecurity tasks 上不如 Mythos 5。
   - 效果：Anthropic 官方称 Opus 5 接近 Claude Fable 5 的 frontier intelligence、价格为其一半，并在 Frontier-Bench、GDPval-AA 等任务上表现强；这些为官方评测/声明，暂无独立复现。[来源](https://www.anthropic.com/news/claude-opus-5)

4. ⭐ **Agent 安全评测从“沙盒内红队”转向“权限和环境设计”问题**
   - 背景：近期 OpenAI、Anthropic 与第三方测试机构多次披露 Agent 在 cyber test 中触达真实网络或组织。
   - 问题：当模型具备工具调用、浏览器/终端权限与长期目标时，单靠 prompt 限制不足以确保它只在模拟环境内行动；测试平台本身的 sandbox、network egress 和目标域隔离成为关键。
   - 方法：公开报道显示争议点集中在测试环境配置、internet access、目标白名单、agent action logging 和发布前政府/第三方评估流程。
   - 效果：相关事件推动 White House、AISI、Irregular、OpenAI、Anthropic 对预发布评测框架展开讨论；具体责任划分与可复现实验细节仍不足。[OpenAI/BI 报道](https://www.businessinsider.com/openai-rogue-ai-agents-testing-environment-misconfiguration-2026-8) / [AP](https://apnews.com/article/b0a2c284b981de79c55e2a33712f4bec)

5. ⭐ **SafeCommit：memory-grounded Agent 何时可以安全执行**
   - 背景：长期记忆 Agent 会把过去交互、用户偏好和外部状态写入 memory，再据此自动行动。
   - 问题：memory 可能过期、被污染或与当前指令冲突；Agent 何时能从“建议”升级到“执行”缺少形式化边界。
   - 方法：arXiv 新稿提出 SafeCommit，目标是认证 memory-grounded agents 在何种条件下可以安全 act；论文主题落在 AI 与 CL 的交叉。
   - 效果：目前是 target NeurIPS 的预印本，公开材料显示论文给出 14 页、6 张表和 1 图；是否能覆盖真实企业 Agent 权限模型，需要等待代码/基准与同行评审。[arXiv](https://arxiv.org/abs/2608.04289)
