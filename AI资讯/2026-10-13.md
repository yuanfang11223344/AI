## 🧠 大模型与 LLM 技术解读

1. 🔥 GPT-6 Sol / Luna 10 月版：从模型发布转向部署安全分层。
   - 背景：OpenAI 已把 GPT-6 系列扩展到 ChatGPT、Codex、ChatGPT Work 与 API，不同产品中同名模型可能对应不同月份版本。
   - 问题：高能力模型进入普通用户流量后，成本、延迟、jailbreak、deception、越权交互和高风险 misuse 都会同时变成产品问题。
   - 方法：OpenAI 以 Sol/Luna 分层覆盖不同价格与使用场景，并通过系统卡按 jailbreak、dishonesty、cyber、bio、violence、自伤等维度披露评估；同时强调 ChatGPT 10 月版与 Codex/Work 中先前版本要区分。
   - 效果：官方称相对 GPT-5.6 对应模型有更强 jailbreak resistance 和 deception 降低，但系统卡也记录 Sol/Luna 在部分 self-harm / gore / sexual content 标准评估上有统计显著回归；暂无独立评测。[来源](https://deploymentsafety.openai.com/gpt-6-october/capability-threshold-critical)

2. 🔥 Mistral Large 4：open-weight frontier 叙事转向“大模型 + 主权算力 + 垂直任务”。
   - 背景：欧洲 AI 公司需要在美国闭源模型与中国 open-weight 模型之间找到差异化，Mistral 把 sovereign AI、欧洲自有数据中心和 open weights 绑定到同一叙事。
   - 问题：企业客户既要强 coding/agentic/multimodal 能力，又担心数据、部署、监管和供应链受制于单一闭源平台。
   - 方法：ML4 采用 natively multimodal MoE，官方披露 1T 参数、49B active parameters，并在 preview 期间先开放 API、继续 red-team，月底再放权重与更多架构细节。
   - 效果：Mistral 声称 ML4 在 cybersecurity、finance、law、visual grounding 等任务上达到 open model 前沿，部分企业任务经第三方 evaluator 测试；权重、完整技术报告与独立复现实验尚未发布，需保留不确定性。[来源](https://mistral.ai/news/mistral-large-4/)

3. ⭐ EmbeddingGemma 2：端侧 multimodal embedding 让 RAG 从“文档检索”扩展到本地多模态记忆。
   - 背景：端侧搜索、个人知识库和 privacy-first RAG 需要低延迟、低成本、可本地运行的 embedding 模型。
   - 问题：上一代轻量 embedding 多聚焦 text；真实个人数据包含图片、音频、视频、代码和混合上下文，跨模态检索一致性更难。
   - 方法：Google DeepMind 将 text、code、image、video、audio 映射到统一 embedding space，强调 lightweight、open 和 on-device。
   - 效果：Google 称 EmbeddingGemma 2 是其最强端侧 multimodal embedding 模型；公开材料偏产品介绍，暂无独立横向评测。[来源](https://blog.google/innovation-and-ai/technology/developers-tools/embeddinggemma-2/)

4. ⭐ RATED：agent tool retrieval 从“语义相关”转向“运行时可靠性”。
   - 背景：AI agents 依赖外部 API、MCP server 和工具链，工具失效、限流或权限异常会直接导致任务失败。
   - 问题：传统 tool retriever 主要优化 query-tool 语义匹配，忽略工具在当前执行环境中的可用性。
   - 方法：论文提出 RATED，用 frozen dual-encoder 做语义匹配，再用 contextual bandit 根据实时执行反馈重排候选工具，并构建 EcoAgent benchmark。
   - 效果：作者称相对 ToolLLM API retriever，RATED 在真实查询上 MRR 相对提升 52.2%，在 30% failure rate 严重 API outage 场景下把 fault selection rate 从 86.2% 降到 2.9%；这是论文实验结果，仍需真实生产 agent 栈验证。[arXiv](https://arxiv.org/abs/2610.13889)

5. ⭐ X-AgentRed：personal agents 的红队评估开始覆盖跨服务组合风险。
   - 背景：个人 agent 通过 browser、email、calendar、file、payment 等工具跨服务行动，单个 harmless request 可能组合成有害路径。
   - 问题：只让 LLM 枚举风险会偏向训练中熟悉的工具组合，可能漏掉新颖的 cross-service harmful path。
   - 方法：X-AgentRed 分析每个工具的 effect、harm 与 precondition，构建 tool dependency graph，再用执行反馈扩展与修正攻击路径。
   - 效果：作者称在四个 frontier agentic models 上，X-AgentRed 的 harmful path rate 是 STAC 的 1.77 倍，tool coverage 平均 2.99 倍；这是红队发现率，不等于真实世界事故概率。[arXiv](https://arxiv.org/abs/2610.13886)
