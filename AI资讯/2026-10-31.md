## 🧠 大模型与 LLM 技术解读

### 1. 🔥 Multi-View MoE：用多路由偏好共同决定专家计算
- **背景**：稀疏 MoE 在固定激活专家预算内扩展总参数量；单路由排序未必贴合专家实际效用。
- **问题**：如何改善专家选择，同时避免对同一专家重复前向计算？
- **方法**：聚合独立初始化路由器的 sigmoid 分数；再用选中专家在各路由器间的相对分数混合潜在视图，调制该专家的输入。每个选中专家仅执行一次前向。
- **效果**：作者在 24 层 10B-A1B、708B token 训练设置下报告九任务平均提升 1.18 个百分点，保持激活专家数量、专家 FLOPs 和 all-to-all 通信量。暂无独立评测；这不等于路由附加成本为零或端到端延迟不变。
- **来源**：[Multi-View MoE](https://arxiv.org/abs/2610.40577)

### 2. ⭐ PIVOT：教师纠正与密集监督共同缓解零奖励
- **背景**：RLVR 遇到困难推理题时，一组采样全部失败会导致缺乏有效奖励信号。
- **问题**：单纯提供教师答案，未必让学生走到可获奖励、又可学习的轨迹。
- **方法**：在学生 rollout 中插入教师纠正片段，并在这些片段上施加 token 级 KL 监督，与 RLVR 目标联合训练。
- **效果**：作者在逻辑游戏中报告 mean avg@8 从最佳基线的 19.5% 升至 35.6%，另测试数学推理。暂无独立评测；avg@8 不是单次回答准确率，也未据此证明实际训练总成本下降。
- **来源**：[PIVOT](https://arxiv.org/abs/2610.40576)

### 3. ⭐ MTA-OPSD：同一回答里的 token 可以选择不同教师
- **背景**：On-policy self-distillation 常用含额外参考信息的教师指导学生。
- **问题**：整次训练或整个回答固定教师，可能忽略 token 之间的监督需求差异。
- **方法**：构建候选教师池，在 token 级自适应选择教师；作者先通过多数投票与 KL 选择的干预实验研究教师偏好。
- **效果**：作者在 Qwen3 数学任务上报告优于现有 OPSD 方法，相对基础模型平均增益最高为 +5.9。暂无独立评测；摘要未充分给出该增益的任务加权细节与总算力账单，不外推到所有任务。
- **来源**：[Every Token Needs Its Own Teacher](https://arxiv.org/abs/2610.40574)

### 4. ⭐ CATT：训练数据归因不能被无关 token 稀释
- **背景**：既有归因评测同时改变多种数据属性，难定位算法失效原因。
- **问题**：文档冗余与词汇干扰可能掩盖真正贡献知识的局部片段。
- **方法**：用虚构知识微调构造明确归因真值，逐项控制变量；将梯度损失改为 negative log-odds，并聚合最高分 token，而非整篇平均。
- **效果**：作者在诊断基准上报告真值召回增加 35—72 个百分点，另在 FTRACE-TREX 测试泛化。暂无独立评测；合成归因改善不能直接解释成真实网页版权归属判定能力。
- **来源**：[Elucidating the Design Space of LM Data Attribution](https://arxiv.org/abs/2610.40655)

### 5. ⭐ ShallowDefend：先作安全决定，再生成回答
- **背景**：单轮拒绝较稳定的模型，在多轮诱导中仍可能失效。
- **问题**：只监督回答表面形式，未必让模型学会明确的安全判断。
- **方法**：采用 Assess → Decide → Respond，先评估意图并输出可解析安全标签，再据此回答；在关键轮通过强化学习训练决定，可用规则奖励或模型裁判。
- **效果**：作者在两个模型家族、14 个基准的受控比较中报告多轮安全领先，效用基本保持但 helpfulness 略有代价。暂无独立评测；摘要没有提供可直接引用的统一攻击成功率降幅。
- **来源**：[ShallowDefend](https://arxiv.org/abs/2610.40627)

### 6. ⭐ Claude API 运维变化：模式兼容与成本归因分别检查
- **背景**：10 月 28—30 日发布记录连续更新请求尺寸、成本分析和 fast mode 生命周期。
- **问题**：依赖旧模式可能在移除日触发错误；用量聚合不足也妨碍按工作流核算成本。
- **方法**：Opus 4.8 的 fast mode 将于 11 月 30 日移除；成本分析 beta 提供 usage/cost 端点与多维分组。第一方 Messages 和 Token Counting 请求体上限升至 128 MB。
- **效果**：官方明确移除后旧模型携带 `speed: "fast"` 会报错。暂无独立评测；请求体大小不等于上下文 token 窗口扩大，迁移模型也需重新评估质量、延迟与成本。
- **来源**：[Claude Platform release notes](https://platform.claude.com/docs/en/release-notes/overview)
