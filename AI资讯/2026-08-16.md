## 🧠 大模型与 LLM 技术解读

### 1. 🔥 Gemini 3.7 Flash：把 coding、agents、thinking budget 做成可调系统参数

- **背景：** Flash 系列承担的是高频生产流量，而不是只服务 benchmark 展示；Google 在 3.6 Flash 后很快推出 3.7 Flash，说明低成本模型迭代频率正在提高。[来源](https://blog.google/innovation-and-ai/models-and-research/gemini-models/introducing-gemini-3-7-flash/)
- **问题：** 企业 agent 需要在质量、延迟和 token 成本之间做稳定权衡；固定推理深度会让简单任务过度计算、复杂任务又推理不足。
- **方法：** DeepMind model card 称 3.7 Flash 基于 Gemini 3.6 Flash，改进 core reasoning foundation，支持文本、图像、音频、视频输入，最高 1M context window，并提供 customizable thinking configurations 控制质量、成本和延迟。[Model card](https://deepmind.google/models/model-cards/gemini-3-7-flash/)
- **效果：** 官方称这是面向 coding 和 agents 的最强 Flash workhorse model；独立基准仍需用真实代码库和工具链复测，当前效果主要来自官方材料。[来源](https://deepmind.google/models/gemini/flash/)

### 2. 🔥 Muse Glimmer：30B open-weight 本地 agent 模型重新定义“可部署”

- **背景：** open-weight 模型竞争从“能聊天”转向“能否在本地长期运行 agent”，核心指标包括显存占用、context cache、function calling、coding 和隐私边界。[来源](https://research.meta.ai/blog/introducing-muse-glimmer-open-agentic-model)
- **问题：** 云端闭源模型成本高、数据边界复杂；但本地模型常在 agent planning、tool use 和长上下文上落后。
- **方法：** Meta 称 Muse Glimmer 是 30B 参数模型，面向 always-on local agent workflows，覆盖 local agents、function calling、local coding 和 LLM-as-a-judge，并以 Apache 2.0 开放权重。[来源](https://research.meta.ai/blog/introducing-muse-glimmer-open-agentic-model)
- **效果：** 官方声称在同尺寸 agentic use cases 和 benchmarks 上有强表现；Hacker News 讨论集中在 30B 级模型的本地显存、上下文缓存与真实工作流评测，独立生产评测仍不足。[HN](https://news.ycombinator.com/item?id=49241679)

### 3. 🔥 Nemotron 3.5 Lightning：LatentMoE + Mamba-2 指向低 active 参数推理

- **背景：** 企业 agent 流量放大后，推理成本比预训练叙事更直接影响采用；NVIDIA 同时卖硬件、NIM 服务和开放模型，模型结构会反向影响 GPU 利用率。[来源](https://catalog.ngc.nvidia.com/orgs/nim/nvidia/models/nemotron-3.5-lightning)
- **问题：** 纯 dense 模型在低延迟、高并发场景成本偏高；普通 MoE 又存在路由、部署和显存管理复杂度。
- **方法：** NGC model card 称 Nemotron 3.5 Lightning 使用 hybrid LatentMoE，交错 Mamba-2、MoE 和部分 Attention 层，30B total、3B active，并配套 speculative decoding 方法提升生成速度。[来源](https://docs.api.nvidia.com/nim/reference/nvidia-nemotron-3-5-lightning-30b-a3b)
- **效果：** NVIDIA 标注该模型 ready for commercial use，Artificial Analysis 称其以较小 total 参数接近更大开放模型表现；第三方任务集仍需按企业内部 agent/coding 数据复测。[来源](https://artificialanalysis.ai/articles/nemotron-3-5-lightning-launch)

### 4. ⭐ ChatGPT Computer History：桌面级上下文记忆进入 Codex/ChatGPT 工作流

- **背景：** Agent 产品正从 chat box 走向桌面 app、文件、浏览器和 IDE，缺少跨 app 上下文会迫使用户不断重述任务背景。[来源](https://help.openai.com/en/articles/6825453-chatgpt-release-notes)
- **问题：** 直接记录屏幕或输入会带来隐私和合规风险；完全不记录又限制 agent 连续工作能力。
- **方法：** OpenAI release notes 称 Computer History 是可选功能，记录 selected apps/websites 的 interaction events，不包含截图、屏幕录制、麦克风或系统音频，且 private browsing 不纳入；ChatGPT/Codex 可引用这些活动延续工作。[来源](https://learn.chatgpt.com/docs/whats-new)
- **效果：** 官方声称能减少重复解释并帮助恢复上下文；但对于企业环境，仍需验证数据保留、管理员策略、敏感 app 排除和 prompt injection 防护，暂无独立安全评测。

### 5. ⭐ AutoDesign / OmniScientist / Intern-S2：scientific agent 开始从 demo 走向长程流程基准

- **背景：** 科研 agent 的难点不是单次问答，而是跨文献、实验设计、评估和迭代的长程任务。[arXiv AutoDesign](https://arxiv.org/abs/2608.13560) / [arXiv OmniScientist](https://arxiv.org/abs/2608.13558)
- **问题：** 现有 agent 容易在长 horizon 中丢目标、评价指标漂移，或只完成浅层文献总结。
- **方法：** AutoDesign 标题指向 meta-harness optimization for long-horizon agentic design；OmniScientist 定位为 omni-modal、omni-discipline AI scientist；Intern-S2-Preview 则明确称 scientific agentic foundation model。[arXiv Intern-S2](https://arxiv.org/abs/2608.13505)
- **效果：** 这些论文说明 scientific agent 研究正在从单工具调用转向任务流程与多模态科学场景；具体效果需阅读全文和复现实验，本文不外推超出论文标题/摘要的结论。
