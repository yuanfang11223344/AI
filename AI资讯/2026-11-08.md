## 🧠 大模型与 LLM 技术解读

### 🔥 GPT-6 Cyber：将安全任务限定在授权操作面

- **背景：** coding/operations Agent 获得工具调用后，漏洞发现与修复可以被串成更长的自动化链路。
- **问题：** 安全能力既要处理真实漏洞，又必须避免越权使用、误报和不可追溯的工具动作。
- **方法：** OpenAI 将 GPT-6 Cyber 描述为用于寻找可利用漏洞、开发修复、并训练为留在授权范围内的模型；索引页没有披露训练数据、agent scaffold 或基准任务配置。
- **效果：** 这是官方产品主张；未见可据此比较真实误报率、修复成功率或滥用拦截率的独立评测。
- **来源：** [OpenAI 产品发布](https://openai.com/news/product-releases/?display=list)

### 🔥 Codex 向代码资产与评审上下文扩展

- **背景：** coding Agent 的难点已从单个补丁延伸到跨仓库历史、依赖、权限和评审流程。
- **问题：** 单轮上下文难以稳定覆盖长期代码知识；代码存储层若与 Agent 割裂，理解和审查都会丢失状态。
- **方法：** OpenAI 公告称将收购 Pierre，并扩展 Codex 的 build、understand、review 工具；未公开检索索引、访问控制模型和推理链路。
- **效果：** 属于整合计划，暂无独立迁移成功率、审查准确率或生产效率评测。
- **来源：** [OpenAI 公司新闻](https://openai.com/news/company-announcements/?display=list)

### ⭐ GPT-6.1 Terra：computer use 的规模化定位

- **背景：** computer use 把视觉、界面状态、规划和受限执行组合为端到端任务。
- **问题：** 页面变化、长链路累计误差与敏感操作授权，都会使“能操作”不等于“可可靠自动化”。
- **方法：** OpenAI 将 GPT-6.1 Terra 定位为可规模化的快速 computer use；该新闻索引没有给出模型结构、训练环境或端到端 benchmark 的可复核细节。
- **效果：** 官方定位不等于独立可靠性结论；应在具体环境中记录成功率、人工接管率与权限拒绝行为。
- **来源：** [OpenAI 产品新闻](https://openai.com/news/product-releases/?display=list)

### ⭐ Agent Skills 的开放标准化信号

- **背景：** Agent 能力逐渐由模型本身扩展到可移植的工作流、工具与领域知识包。
- **问题：** 不同 Agent 平台若无法复用技能描述，会造成提示词、执行约束和工具权限的重复实现。
- **方法：** Anthropic 新闻页称已将 Agent Skills 捐给 Agentic AI Foundation，并列举多个集成平台；页面未披露统一的安全认证或互操作测试细节。
- **效果：** 这是生态治理与接口采用信号，而不是对某项任务性能的独立基准；暂无独立评测。
- **来源：** [Anthropic Newsroom](https://www.anthropic.com/news)

### 📌 强到弱监督与 GRPO 的算力效率比较

- **背景：** reasoning/post-training 往往由采样、验证和优化共同推高训练预算。
- **问题：** 强模型监督能否在既定算力下有效迁移到弱模型，取决于数据、奖励与评测设置。
- **方法：** 预印本比较 Strong-to-Weak OPD 与 GRPO 的 compute efficiency；应以正文的 FLOPs、模型规模和基准设置解读，不能只从标题推断优劣。
- **效果：** 仅为作者实验报告，暂无独立复现。
- **来源：** [arXiv:2611.08453](https://arxiv.org/abs/2611.08453)
