## 🧠 大模型与 LLM 技术解读

### 🔥 GPT-6.2 Astra / Sol：把能力分层映射到推理与 agent 工作流
- **背景**：模型平台正将高难推理/coding 与日常多步骤任务拆成不同成本、吞吐与风险档位。
- **问题**：单一旗舰模型往往难以同时满足复杂任务质量、响应速度和预算约束。
- **方法**：OpenAI 在 API 中提供 Astra 与 Sol；官方 changelog 指出二者支持文本/图像输入、文本输出，工具调用走 Responses API。
- **效果**：官方称两者相较前代在高难任务上更少生成 token；未在 release notes 中给出可复现的完整横向基准，暂无独立评测。[来源](https://developers.openai.com/api/docs/changelog)

### 🔥 Gemini 4 Neon：模型卡成为能力声明的审查入口
- **背景**：多家前沿实验室在同月密集更新模型，产品名本身不足以判断可用范围与风险。
- **问题**：缺少结构化文档时，开发者难以核对训练、评测、已知限制与部署前提。
- **方法**：Google DeepMind 将 Gemini 4 Neon 列入模型卡目录，并标记为 11 月 18 日更新；模型卡机制以结构化页面承载模型信息。
- **效果**：该目录确认更新事实，但搜索结果未提供可用于复现的完整性能表；对具体能力与限制应以模型卡正文为准，暂无独立评测。[来源](https://deepmind.google/models/model-cards/)

### ⭐ Microsoft 多模型策略：专用模型与 frontier 模型并行
- **背景**：企业采购不再只购买单一聊天模型，而需要按任务、治理与成本接入模型组合。
- **问题**：把所有负载送入最大模型会放大时延、成本与数据治理复杂度。
- **方法**：Microsoft 在 Ignite 发布六个模型；Axios 转述其将部分模型定位为能以更低成本覆盖特定任务，并继续推进通用 frontier 模型。
- **效果**：报道属于公司发布与采访信息，未提供第三方统一测试方法或原始逐项数据；“比肩”类说法不可直接视为独立结论。[来源](https://www.axios.com/2026/11/17/microsoft-ai-models-openai-anthropic-ignite)

### ⭐ Business Agents：把工具调用延伸到商家交互
- **背景**：LLM agent 从开发者工具逐步进入发现、咨询和交易前的用户路径。
- **问题**：用户需要实时商家信息，但 agent 的权限范围、内容责任与人工接管机制必须清楚。
- **方法**：OpenAI 推出 Businesses in ChatGPT beta，允许符合条件的美国商家建立资料，并提供 Business Agent 进行后续问答。
- **效果**：官方称这是早期 beta，并未公布转化率、准确率或安全事件统计；暂无独立评测，接入方应先验证数据更新和升级人工流程。[来源](https://openai.com/index/introducing-businesses-chatgpt/)

## 🛠️ 工具/开源

- ⭐ [agent-browser](https://github.com/vercel-labs/agent-browser)：Rust CLI/daemon 的浏览器自动化项目，提供可访问性快照、语义定位与 MCP server 入口；适合评估 agent browser 工具的可观测性设计。
- ⭐ [Model Context Protocol](https://github.com/modelcontextprotocol/modelcontextprotocol)：MCP 规范与生态入口；接入时仍需落实 server allowlist、最小权限和审计日志。
- ⭐ [ReMCP](https://github.com/getremcp/remcp)：面向显式配对设备的远程 MCP 访问项目，涵盖文件、终端、桌面 UI 与浏览器自动化；应先审查配对与权限模型。
- 📌 [OpenAI Agents API](https://openai.com/index/introducing-the-agents-api/)：官方托管 agent API，强调运行环境、工具、上下文与子 agent 协调，适合作为生产运行时的对照样本。
