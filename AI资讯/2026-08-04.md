## 🧠 大模型与 LLM 技术解读

1. 🔥 **GPT-Live：把语音 Agent 从“轮次制”推进到 full-duplex 连续推理**  
   - 背景：语音助手正在从问答入口升级为可调用工具、控制桌面和协调 Agent 的实时界面。  
   - 问题：传统 cascaded 或 turn-based 语音系统依赖 turn detector，容易出现抢话、等待和工具调用阻塞，难以满足自然对话的亚秒级节奏。  
   - 方法：GPT-Live 使用 full-duplex voice model，让音频输入/输出持续流动；把深度 reasoning、search、tool use 放到异步 delegation 路径，并通过 stateful inference、context compaction、WebRTC/WARP/Instant Connect 降低启动和长会话延迟。  
   - 效果：OpenAI 称新 Go 媒体前端让 frame delivery 的 p95 接近旧系统 p50，WARP 将媒体/数据启动从 6 次网络往返压缩到 1 次；暂无独立评测。来源：[OpenAI](https://openai.com/index/continuous-voice-interaction-with-gpt-live/)

2. 🔥 **GPT-5.6 efficiency stack：模型能力之外的 inference/harness 优化成为竞争点**  
   - 背景：frontier model 需求增长快于算力供给，模型公司必须同时优化质量、延迟、可用性和单位成本。  
   - 问题：单个模型参数效率不等于服务效率；路由、调度、KV/cache、kernel、tool loop、context bloat 都会吞掉成本优势。  
   - 方法：OpenAI 把优化重点放到 routing、scheduling、kernel optimization、caching、model implementation 与 agentic harness，并称 GPT-5.6 Sol 参与了多项系统优化。  
   - 效果：公开材料强调同硬件服务更多 token、Fast mode 在 GPT-5.6 Sol 上可比 Standard 快至 2.5x；具体第三方成本/质量复现仍缺失。来源：[OpenAI Engineering](https://openai.com/index/gpt-5-6-frontier-intelligence-efficiency/)、[OpenAI Product](https://openai.com/index/advancing-the-price-performance-frontier-with-gpt-5-6/)

3. ⭐ **Gemini Robotics ER 2：VLM + tool orchestration 转向 embodied Agent**  
   - 背景：机器人 Agent 需要把视觉、视频、空间关系、任务进度和工具/多机器人编排放在同一个推理链条中。  
   - 问题：普通多模态模型擅长识别和描述，但面对物理动作时需要更可靠的空间推理、时间推理和阻塞式工具调用安全边界。  
   - 方法：Gemini Robotics ER 2 基于 Gemini 3.5 Flash，提供标准 preview 与 streaming preview 两个 endpoint，覆盖视频 moment finding、progress classification、multi-robot orchestration、multi-step tool use。  
   - 效果：Google 标注其为 preview；官方给出能力范围，但暂无独立机器人基准评测。来源：[Gemini changelog](https://ai.google.dev/gemini-api/docs/changelog)、[Gemini Robotics ER](https://ai.google.dev/gemini-api/docs/robotics-overview)

4. ⭐ **MiniMax H3 + ComfyUI：视频生成模型更强调原生音频、多模态上下文与 motion transfer**  
   - 背景：视频生成工具链正在从单一 text-to-video 走向 image/audio/video prompt 混合控制。  
   - 问题：真实创作工作流需要保留角色、镜头运动、音频节奏和局部编辑能力，单一 prompt 往往可控性不足。  
   - 方法：ComfyUI 的 day-0 支持文章称 H3 可同时处理 image、audio、video，并支持 native stereo audio、editing 与 motion transfer。  
   - 效果：公开材料展示为工具链集成与样例输出，暂无独立评测；对本地节点式视频工作流有较高可试用价值。来源：[ComfyUI Blog](https://blog.comfy.org/p/minimax-h3-day-0-support-in-comfyui)、[HN discussion](https://news.ycombinator.com/item?id=49155629)

5. ⭐ **AirLLM：用 layer/expert streaming 把超大开放模型推理搬到低显存设备**  
   - 背景：开放模型参数规模持续膨胀，本地推理的瓶颈从 FLOPs 扩展到 VRAM 与模型装载。  
   - 问题：70B/405B/MoE 模型通常需要高显存或量化；这限制了研究者在消费级/工作站设备上做验证。  
   - 方法：AirLLM 只把当前层或 MoE token 实际路由到的 expert 放入 GPU，README 称无需 quantization、distillation 或 pruning 即可降低显存占用。  
   - 效果：项目 README 声称 70B 可在 4GB GPU、Llama 3.1 405B 可在 8GB、Kimi K3 2.8T 可在 3.72GB VRAM 运行；速度和吞吐仍需按场景复现。来源：[GitHub](https://github.com/lyogavin/airllm)、[HN discussion](https://news.ycombinator.com/item?id=49154228)
