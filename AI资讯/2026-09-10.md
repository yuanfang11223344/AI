## 🧠 大模型与 LLM 技术解读

1. 🔥 **GPT-6 Astra：从通用模型到 cyber-critical frontier system**
   - 背景：OpenAI 在 2026-09 发布 Astra，定位为其最强广泛部署模型，并接入 ChatGPT Work、Codex 与 API。
   - 问题：高能力模型同时具备 coding、browsing、computer use 和 cyber exploitation 能力，发布边界、监控和滥用防护成为核心瓶颈。
   - 方法：Astra 结合 pre-training、reinforcement learning、alignment 与工具使用能力；OpenAI 用 Preparedness Framework 标记 Critical cybersecurity capability，并配置 system card、访问分级和 red-teaming。
   - 效果：OpenAI 声称 Astra 在 FrontierMath Tier 4、ARC-AGI-3、ExploitBench 等指标上达到极高分数；这些为厂商披露数据，暂无足够独立生产评测。来源：[OpenAI](https://openai.com/index/gpt-6-astra/)、[System Card](https://deploymentsafety.openai.com/gpt-6-astra)
2. 🔥 **AI-generated Navier-Stokes proof：科学 Agent 的可审计路径**
   - 背景：数学证明是检验 AI 科学推理的高门槛任务，尤其需要符号严谨性和同行复核。
   - 问题：自然语言推理容易出现 hallucination，科学发现型 Agent 必须提供可检查中间产物。
   - 方法：OpenAI 称内部系统产出解析证明与 Lean formalization，试图用形式化证明降低验证难度。
   - 效果：公开材料声称解决 Millennium Prize 问题相关陈述；独立数学审查尚未完成，结论应保守引用。来源：[OpenAI Navier-Stokes](https://openai.com/index/navier-stokes-solution/)
3. 🔥 **Claude Mythos/Fable 5.1 与外部安全测试边界**
   - 背景：Anthropic 将 Mythos/Fable 5.1 作为 coding、knowledge work、science 方向的最新模型线。
   - 问题：当模型能力触达 cybersecurity 与 life sciences，高风险模型是否必须给国家 AISI 或第三方机构做预发布评估成为争议点。
   - 方法：Anthropic 公开页强调模型能力和 safety positioning；FT 报道显示访问权限可能受政府协调和地缘政策影响。
   - 效果：产业影响明确，但公开技术细节和独立评测不足；需要继续跟踪 Anthropic system card 与第三方 eval。来源：[Anthropic](https://www.anthropic.com/)、[FT](https://www.ft.com/content/560e1c8b-f163-4fd6-b604-e905550ac870)
4. ⭐ **Speculative decoding 新论文：X-CoSD 与 Osprey**
   - 背景：长上下文与 agent 多轮调用让 LLM serving 延迟和成本持续上升。
   - 问题：传统 speculative decoding 假设 drafter 与 target model 共享词表或任务分布，跨模型/跨设备容易失效。
   - 方法：X-CoSD 研究 cross-vocabulary collaborative speculative decoding；Osprey 用 target-agnostic pre-training 提高 drafter 对不同目标模型的泛化。
   - 效果：两篇论文都指向推理加速，但仍需在真实生产模型、混合词表和端云协同环境中验证。来源：[arXiv:2609.09166](https://arxiv.org/abs/2609.09166)、[arXiv:2609.09338](https://arxiv.org/abs/2609.09338)
5. ⭐ **Agent workflow 评测：OpenDiscoveryTrace / Hybrid Deep Research / RobustSGPO**
   - 背景：Agent 工程开始从“能完成任务”转向“过程可审计、可复现、可优化”。
   - 问题：只评估最终答案会掩盖错误路径、不可复现工具调用和失败恢复问题。
   - 方法：OpenDiscoveryTrace 关注 AI scientist process traces；Hybrid Deep Research 评测数据库查询与 Web search 混合证据；RobustSGPO 控制 agent harness evolution 的搜索空间。
   - 效果：这些工作提供评测与优化框架，不等同于某个模型能力突破；对 Codex/Claude Code 类系统的工程化很有参考价值。来源：[arXiv:2609.09203](https://arxiv.org/abs/2609.09203)、[arXiv:2609.09410](https://arxiv.org/abs/2609.09410)、[arXiv:2609.09646](https://arxiv.org/abs/2609.09646)
6. 📌 **Ternary / low-bit LLM：QTEA 与 Qwen3-8B ternarisation**
   - 背景：推理成本受 memory bandwidth、cache 与权重搬运限制，低 bit 模型对边缘与私有化部署重要。
   - 问题：低于 2-bit 的 PTQ 往往损失精度，且“1.58-bit”标签不等于真实可执行表示。
   - 方法：QTEA 结合 sparse residual salient weight 与 by-column optimization；Qwen3-8B ternarisation 论文关注 capability retention、lossless packing 与 packed execution。
   - 效果：论文声称改善超低 bit 推理可用性；还需看开源实现、kernel 性能和真实任务精度。来源：[arXiv:2609.00224](https://arxiv.org/abs/2609.00224)、[arXiv:2609.09240](https://arxiv.org/abs/2609.09240)
