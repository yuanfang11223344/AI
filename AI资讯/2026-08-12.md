## 🧠 大模型与 LLM 技术解读

1. 🔥 OpenAI GPT-5.6-Cyber / Daybreak Red
   - 背景：前沿模型的 cyber capability 已经进入企业防御、漏洞研究和政策监管的交界区，普通安全 guardrail 会阻断部分合法防御工作。
   - 问题：如何让可信防御者使用更强 cyber model，同时避免将高风险 exploit capability 直接开放给未授权用户。
   - 方法：OpenAI 采用 Daybreak Blue/Red 分级访问、身份验证、scope 定义、monitoring、hardware security key 要求和 approved-use restrictions；GPT-5.6-Cyber 在 GPT-5.6 Sol 上针对 exploit development、zero-day discovery、vulnerability report writing 等任务继续训练。
   - 效果：OpenAI 称 GPT-5.6-Cyber 在内部 Advanced Cybersecurity Completion Rate 上完成率为 95.0%，而 GPT-5.6 Sol 为 1.5%；同时披露其曾帮助发现并上报 Chrome V8 高危漏洞 CVE-2026-15903。该指标为 OpenAI 内部评测，暂无独立复现。来源：[OpenAI Daybreak](https://openai.com/index/expanding-daybreak-as-the-cyber-defense-window-narrows/)
2. 🔥 NVIDIA Nemotron 3.5 Lightning
   - 背景：长时间运行的 coding/security/business agents 通常不是每一步都需要 frontier reasoning model，执行层大量 token 花在工具调用、结果校验和子任务分派。
   - 问题：用大模型处理每个 execution step 会导致延迟和成本上升，本地/边缘/企业私有部署也需要更小但足够强的开放模型。
   - 方法：Nemotron 3.5 Lightning 是 30B parameter、3B active parameter 的 open MoE 模型，结合 harness-optimized training、speculative decoding、多 token prediction、NVFP4/BF16 checkpoints，并由 NeMo Switchyard 将复杂规划路由到 frontier model、将高频执行路由到 Lightning。
   - 效果：NVIDIA 称其相对同类模型最高可达 4x output speed，并在 PinchBench 中以相近 accuracy 比 Qwen3.6 35B 快 30% 完成 10,000 tasks；这些为 NVIDIA/Artificial Analysis/PinchBench 口径，仍需独立生产 workload 复核。来源：[NVIDIA Technical Blog](https://developer.nvidia.com/blog/nvidia-nemotron-3-5-lightning-delivers-fast-accurate-specialized-task-execution-for-long-running-agents/)、[NeMo Switchyard](https://developer.nvidia.com/blog/route-ai-agent-workloads-across-models-with-nvidia-nemo-switchyard/)
3. ⭐ NeMo Switchyard 的 model routing
   - 背景：agent system 正从单模型 prompt 转向 system of models，不同模型承担 planning、execution、verification、domain specialist 等角色。
   - 问题：如果开发者手写路由逻辑，应用需要绑定具体模型和 provider，难以在成本、latency、accuracy 之间动态取舍。
   - 方法：Switchyard 提供开放路由库，把 Nemotron 3.5 Lightning、Claude Opus 等模型作为 routing targets，以 escalation router 等策略决定何时调用 frontier model。
   - 效果：NVIDIA 披露在五次运行中，将 Nemotron 3.5 Lightning 与 Claude Opus 4.8 路由组合相比 frontier-only baseline 降低 74% 成本，只把 7% calls 发给 frontier model，但 accuracy 约下降 6 个百分点；暂无第三方复现实验。来源：[NVIDIA NeMo Switchyard](https://developer.nvidia.com/blog/route-ai-agent-workloads-across-models-with-nvidia-nemo-switchyard/)
4. ⭐ SHE：Trajectory-driven Safety Harness Evolution for LLM Agents
   - 背景：LLM agent 的安全性不只由模型权重决定，还由 system prompt、memory、tool policy、runtime control 等 harness 层共同决定。
   - 问题：固定 harness 难以随新风险演进，而且多个组件耦合后很难判断是哪一层导致 unsafe trajectory。
   - 方法：论文将 harness 分解为 System Prompt、Rule Bank、Safety Memory、Tool Policy 四类 artifact，用 rollout trajectory 中的失败案例做 attribution-guided evolution，再通过 safety-utility validation 选择更新后的 harness。
   - 效果：摘要称在 Agent-SafetyBench 上相比 static SafeHarness 将 ASR 降低 3.1x，并能迁移到 held-out AgentHarm；仍需关注 benchmark 构造、演化预算与真实工具环境泛化。来源：[arXiv:2608.09885](https://arxiv.org/abs/2608.09885)
5. ⭐ The Knowing-Saying Gap
   - 背景：LLM confidence 与内部 representation probes 的关系直接影响 calibration、AI safety 和 model monitoring。
   - 问题：模型可能在内部表征中“知道”答案有问题，但外显 confidence 没有反映错误风险，导致用户和系统过度信任输出。
   - 方法：论文研究 probes 发现错误与模型自报 confidence 之间的 gap，试图区分 representation-level error signal 和语言层面的 uncertainty reporting。
   - 效果：目前公开列表只给出题名与元数据，具体实验结论需阅读全文；不能据此推断已解决 calibration。来源：[arXiv:2608.07528](https://arxiv.org/abs/2608.07528)、[arXiv cs.AI new](https://arxiv.org/list/cs.AI/new)
6. ⭐ EvoHarness-RL / TraceCompiler 代表 agent harness 的两条路线
   - 背景：长程 agent 需要记忆、进度、经验复用和可重复流程，单纯扩大 context window 不等于可靠执行。
   - 问题：一个方向是让 agent 学会何时读写外部 harness state，另一个方向是从 noisy traces 中提炼 deterministic workflow，减少重复探索。
   - 方法：EvoHarness-RL 用 BPE harness state 和 cost-aware GRPO 学习外部状态协调；TraceCompiler 从重复 agent traces 中挖掘可复用结构并编译成 mostly deterministic workflows。
   - 效果：EvoHarness-RL 摘要称 Qwen3-8B 在 ALFWorld 达到 96.9% success；TraceCompiler 摘要强调将 noisy traces 转成可执行流程。两者仍需看代码、任务覆盖和生产工具链兼容性。来源：[arXiv:2608.05446](https://arxiv.org/abs/2608.05446)、[arXiv:2608.02680](https://arxiv.org/abs/2608.02680)
