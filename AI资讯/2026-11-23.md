## 🧠 大模型与 LLM 技术解读

### 1. 🔥 GPT-6.2 Astra / Sol：模型分层落到 API 与 Agent 工程

- **背景**：前沿模型正同时服务高难度专业任务与高频 Agent 工作流，单一旗舰模型难以兼顾交互延迟、成本和能力上限。
- **问题**：开发者需要在复杂推理/coding 与可规模化多步骤执行间选择，并需要稳定的工具调用接口。
- **方法**：OpenAI 将 Astra 和 Sol 作为两个 API 型号发布；两者接受文本和图像并输出文本，工具调用经 Responses API。官方还提供 2/8 小时 background completion 窗口及相对 Standard 的费率折扣安排。
- **效果**：官方称两者在高难任务上优于前代且输出 token 更少；公开资料没有给出可跨供应商直接复核的统一真实工作负载测量，暂无独立评测。[模型 release notes](https://help.openai.com/en/articles/9624314-model-release-notes) · [API changelog](https://developers.openai.com/api/docs/changelog)

### 2. 🔥 GPT-6.2 的能力提升伴随更强的高风险访问控制

- **背景**：模型用于 coding、browser 与 computer use 后，网络安全和生物风险评估不再只是模型卡附录，而影响产品路由与访问资格。
- **问题**：能力上升会提高从已知漏洞到可用 exploit 的辅助风险，不能只依赖通用提示词拒答。
- **方法**：system card 说明模型评估达到了相应 Preparedness 阈值；对更宽松的 cyber 访问要求额外 vetting，并收紧默认高风险协助限制。
- **效果**：这是 OpenAI 的内部评估与部署措施声明，不是第三方安全认证；其价值在于把模型级能力评估映射为 API 的权限边界。[GPT-6.2 system card](https://deploymentsafety.openai.com/gpt-6-2-astra-sol/internal-deployment-of-gpt-6.2-astra-and-gpt-6.2-sol)

### 3. ⭐ TideCache：hybrid LLM 的 KV cache 从“内存容量”变成调度问题

- **背景**：含 global-attention 与 bounded-state 层的 hybrid 开源模型，使不同层的 cache 形态和驻留需求不再一致。
- **问题**：长上下文与高并发 Agent 会争抢 HBM；简单把 KV cache 留在 GPU 会限制并发，迁移又会拖慢 TTFT。
- **方法**：论文在 SGLang 中提出 Transparent Cache Pool、layer-wise Cache Streamer 和请求调度器：按层复用 GPU slot、将可流式部分预取，已生成 KV 保持驻留。
- **效果**：作者在 GB300/GH200、七组模型/平台配置上报告，完成 Agent turns 最多提高 2.04×、P50 token latency 降 20–59%、Agent P50 TTFT 提高 1.40–3.05×；均为论文作者结果，尚待独立复现。[论文](https://arxiv.org/abs/2611.26619)

### 4. ⭐ AutoMaster：让模型自己设计 post-training 干预

- **背景**：用成功轨迹做 SFT/RL 仍会把无依据假设、重复验证等低质量习惯一并蒸馏。
- **问题**：只以任务成败标注，难以指出“哪种过程行为”值得保留或抑制。
- **方法**：论文的 Skill-FT 用自然语言 skill 约束 teacher rollout；AutoMaster 再以 Agent 执行轨迹分析、skill 设计、数据选择和反馈闭环，自动构造 post-training 干预。
- **效果**：论文报告该方法在其设置中改进训练轨迹质量；需要关注 benchmark、教师/学生同源性和成本，暂无独立评测。[论文](https://arxiv.org/abs/2611.26510)

- **AutoMaster**（Chen et al., 2026-11-20）：用自然语言 skill 驱动的 Agent 闭环自动设计 post-training 数据干预。[arXiv](https://arxiv.org/abs/2611.26510)

- **AgentRoboCritic**（Du et al., 2026-11-19）：提出在 12 个 manipulation benchmark 上用动作级 intent/critic 分析 frontier agent 的直接机器人控制失误。[arXiv](https://arxiv.org/abs/2611.26613)
- **O²LaF**（Jiang et al., 2026-11-19）：复用预训练 video DiT，同时建模 inverse/forward dynamics 以从无标注视频学习 latent action。[arXiv](https://arxiv.org/abs/2611.26617)

## 🛠️ 工具/开源

- ⭐ **agent-browser**：Vercel Labs 的浏览器自动化 CLI/daemon，提供可访问性快照、语义定位及 MCP server；适合审查 Agent browser 的可观测性和权限收口。[GitHub](https://github.com/vercel-labs/agent-browser)
- ⭐ **AG-UI**：Agent 与用户界面的事件协议，强调双向 typed event stream，可用来减少框架私有 glue code；部署前仍要明确事件中的敏感状态流向。[GitHub](https://github.com/ag-ui-protocol/ag-ui)
- ⭐ **Model Context Protocol**：检查 MCP server 的能力声明、transport 与版本变更的规范入口；生产接入应使用 allowlist、最小权限与审计日志。[规范](https://modelcontextprotocol.io/specification/2025-06-18)
