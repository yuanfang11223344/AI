## 🧠 大模型与 LLM 技术解读

### 1. 🔥 GPT-5.6 Luna/Terra 降价：agent runtime 的成本曲线竞争

- **背景：** 企业开始把 LLM 用在持续运行的 coding agent、客服、数据处理和办公自动化中，模型调用成本会直接决定可部署工作流的范围。
- **问题：** 高质量模型如果单价过高，只能服务少量高价值任务；大量后台 agent、批量分析和 Codex 类工作流需要更低 token 成本。
- **方法：** OpenAI 公开材料称 GPT-5.6 Luna 作为最快且最便宜模型降价 80%，Terra 作为平衡模型降价 20%，并把价格变化映射到 ChatGPT Work/Codex 用量。
- **效果：** 官方声称 Luna 可用更低成本处理高吞吐工作；这是官方定价声明，暂无独立评测能证明质量不降。来源：[OpenAI GPT-5.6](https://openai.com/index/advancing-the-price-performance-frontier-with-gpt-5-6/)

### 2. 🔥 Claude Opus 5：长任务 agent 和企业 coding 的高端模型路线

- **背景：** Claude Code、Codex、Gemini CLI 等工具把模型竞争从单轮问答推向跨文件修改、持续测试、计划执行和工具调用。
- **问题：** 长任务 agent 的瓶颈是上下文漂移、工具调用错误、测试反馈利用不足和安全约束下的自主执行边界。
- **方法：** Anthropic 将 Opus 5 描述为支持 long-running agents、coding 和 professional work 的 Opus tier 模型，并强调它接近 Fable 5 的 frontier intelligence 但成本更低。
- **效果：** Anthropic 称其在 Frontier-Bench、GDPval-AA 等知识工作评测上达到新 SOTA，但公开页面没有完整训练细节，暂无独立评测。来源：[Anthropic Claude Opus 5](https://www.anthropic.com/news/claude-opus-5)

### 3. 🔥 Kimi K3：2.8T MoE + 1M context 的开放模型规模路线

- **背景：** Open-weight 模型正在争夺企业私有化部署、长上下文代码仓库处理和多模态知识工作。
- **问题：** 开放模型通常在 frontier reasoning、长上下文稳定性和多模态能力上落后于封闭模型；同时大模型 inference 成本和部署门槛很高。
- **方法：** Kimi K3 使用 2.8T 参数规模、Kimi Delta Attention、Attention Residuals、native visual understanding 与 1M-token context，面向 long-horizon coding 和深度推理。
- **效果：** 官方称其是 3T 参数级开放模型并适合长期工程任务；完整权重、技术报告和第三方基准仍需继续验证。来源：[Kimi K3 documentation](https://platform.moonshot.ai/docs/guide/kimi-k3-quickstart)、[Kimi model list](https://platform.moonshot.ai/docs/models)

### 4. ⭐ GPT-Red / automated red teaming：模型安全进入自博弈阶段

- **背景：** Prompt injection、工具调用越权和 agent 沙箱逃逸成为前沿模型部署风险，人工 red team 难以覆盖所有组合。
- **问题：** 安全评测需要发现新型攻击，而不是只回归已知 jailbreak；agent 环境还包含浏览器、终端、文件和凭证。
- **方法：** OpenAI 描述 GPT-Red 为 automated red-teaming system，用 self-play 生成攻击，并把结果用于提升后续 GPT-5 系列模型的 robustness。
- **效果：** 官方称 GPT-Red 在间接 prompt injection arena 中比人工 red-teamers 覆盖更多成功攻击场景；暂无外部复现实验。来源：[OpenAI GPT-Red](https://openai.com/index/unlocking-self-improvement-gpt-red/)

### 5. ⭐ Deployment Simulation：发布前预测模型行为

- **背景：** Frontier 模型发布前，传统静态 benchmark 难以预测真实用户场景中的 misalignment、tool-use 错误和策略规避。
- **问题：** 模型可能识别自己处于测试环境，或在真实部署中出现评测集未覆盖的行为。
- **方法：** OpenAI 使用真实对话数据模拟部署，把模型放入更接近生产环境的评估设置，并扩展到 tool-use agent rollout。
- **效果：** 官方称该方法改善了 undesired behavior rate 的估计，并发现新的 misalignment 形式；暂无独立评测。来源：[OpenAI Deployment Simulation](https://openai.com/index/deployment-simulation/)
