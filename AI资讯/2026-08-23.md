## 🧠 大模型与 LLM 技术解读

1. 🔥 **Agentic coding 从“代码补全”转向“任务执行系统”**  
   - 背景：OpenAI、Anthropic 与 IDE 生态都在把模型接入 shell、文件系统、Git 和项目上下文。  
   - 问题：单轮代码生成难以处理跨文件修改、测试失败回滚、权限边界和长任务状态管理。  
   - 方法：当前主流方案是把 LLM 放入带工具调用、文件读写、测试执行、差异审查和人工批准的 loop 中，用上下文压缩和任务记忆维持多步执行。  
   - 效果：公开材料显示该路线更适合真实工程任务，但不同产品对可复现评测、长任务成功率和安全边界披露仍不充分，暂无统一独立评测。[来源](https://openai.com/codex/)

2. 🔥 **Claude 系列的企业化重点是长上下文、代码与安全策略协同**  
   - 背景：Anthropic 近年的 Claude 产品线持续强调 coding、文档理解、企业权限与模型安全。  
   - 问题：企业用户需要模型处理大代码库和长文档，同时避免越权访问、错误自动执行和不可审计输出。  
   - 方法：Claude 生态通常把长上下文模型、工具使用、Artifacts/代码工作流、企业管理策略和安全评估结合使用。  
   - 效果：官方材料证明产品方向明确，但具体任务成功率和横向对比仍依赖第三方评测；对新发布能力若只有官方声明，应视为暂无独立评测。[来源](https://www.anthropic.com/news)

3. ⭐ **Gemini/DeepMind 多模态路线强调模型能力与科学工具结合**  
   - 背景：Google DeepMind 持续把 Gemini、多模态理解、推理和科学 AI 放在统一研究叙事下。  
   - 问题：通用 LLM 在科学场景中面临可验证性、专业工具调用、数据来源和长链推理稳定性问题。  
   - 方法：路线是把多模态 foundation model 与检索、实验工具、结构化评测和特定领域数据结合。  
   - 效果：官方博客展示了多个研究方向，但不同任务的独立复现程度不同；没有第三方数据的发布应标注为暂无独立评测。[来源](https://deepmind.google/discover/blog/)

4. ⭐ **开源 LLM 竞争进入“推理效率 + 可部署性”阶段**  
   - 背景：Hugging Face、GitHub 与开源社区持续发布模型、量化方案、推理框架和评测脚本。  
   - 问题：开放模型不只要参数和许可证，还要解决推理显存、吞吐、上下文扩展、工具调用格式和企业私有部署。  
   - 方法：社区常用权重量化、KV cache 优化、vLLM/TensorRT-LLM 类服务化框架、LoRA/adapter 微调和标准化 eval harness。  
   - 效果：开源路线在成本和可控性上有优势，但模型质量、数据污染和真实 Agent 任务评测仍需要逐项验证。[来源](https://huggingface.co/blog)

5. 📌 **LLM 评测重点从静态 benchmark 转向真实工作流**  
   - 背景：MMLU、HumanEval 等静态基准长期被用于发布会叙事，但 Agent、代码和企业搜索任务更接近真实需求。  
   - 问题：静态题库容易过拟合或被数据污染，不能反映长上下文、工具调用、权限失败和多步纠错能力。  
   - 方法：更可靠的评测需要任务级 sandbox、可审计工具日志、失败分类、成本统计和人工复核。  
   - 效果：OpenAI、Anthropic、Google 等官方材料都在强调实际任务能力，但跨厂商可复现评测仍不足，暂无统一独立评测。[来源](https://github.com/swe-bench/SWE-bench)
