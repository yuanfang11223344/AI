## 🧠 大模型与 LLM 技术解读

### 1. 🔥 Qwen3.8-Flash-Next：用 Hybrid Attention、Gated Residual 和 N-gram Embedding 降低长上下文 agent 成本

- 背景：Qwen 团队把 Qwen3.8-Flash-Next 定位为 Qwen4 架构预览，面向多模态、长上下文和 agentic workloads。
- 问题：长上下文 agent 的主要瓶颈是注意力计算、KV cache、推理延迟和参数扩展成本；纯 MoE 扩参对显存与调度也有压力。
- 方法：模型卡披露主模型 125B 参数、每 token 激活 6B，另有 51B N-gram embedding 和 4B MTP；结构上采用 Gated DeltaNet + Qwen Sparse Attention（QSA）、Gated Residual、N-gram Embedding，并支持原生 262,144 上下文、可扩展到 1,000,000 tokens。
- 效果：官方表格给出 SWE-bench Pro 62.5、CoWorkBench 73.9、Toolathlon Verified Pass@1 73.5 等结果；这些是厂商/模型卡口径，仍需独立复测，尤其要验证不同 serving engine 下的吞吐、延迟和上下文稳定性。[Qwen blog](https://qwen.ai/blog?id=qwen3.8-flash-next) / [Hugging Face](https://huggingface.co/Qwen/Qwen3.8-Flash-Next)

### 2. 🔥 GLM-5.3-Flash：320B 总参数、18B 激活参数的开源多模态 Flash 模型

- 背景：Z.ai 在 Ox Alpha 匿名预览后发布 GLM-5.3-Flash，面向低成本、多模态和长上下文推理市场。
- 问题：开源模型要在能力、服务成本、上下文长度和国产算力适配之间同时竞争；匿名预览虽能收集真实反馈，但也增加评测来源不透明度。
- 方法：Z.ai 文档称模型为 320B total / 18B activated，采用 sparse attention + linear attention hybrid architecture，并用 IndexPool 降低长上下文索引开销；官方还称支持 1M-token context。
- 效果：官方宣称相比 GLM-5.3 注意力计算与 KV cache 体积分别下降，Business Insider 报道 Ox Alpha 曾成为当周热门模型；但公开材料主要来自厂商和媒体，独立 benchmark 仍需等待。[Z.ai blog](https://z.ai/blog/glm-5.3-flash) / [Z.ai docs](https://docs.z.ai/guides/vlm/glm-5.3-flash) / [Business Insider](https://www.businessinsider.com/ox-alpha-zai-chinese-internet-celebrate-weibo-glm53-flash-2026-8)

### 3. 🔥 Anthropic MHS：从 tool calling 到实验设备控制的 agent 标准化尝试

- 背景：Claude Science 已经面向科研任务；MHS 进一步把 agent 接入物理实验设备，进入生物、制造和工程工作流。
- 问题：物理设备控制需要安全边界、设备语义、可审计动作、误操作防护和实验可复现性，不能只靠自然语言工具调用。
- 方法：MHS 作为共享 specification，让 Claude agent 通过标准接口操作设备，并在研究预览中覆盖液体处理等实验环节。
- 效果：Anthropic 披露在 held-out 实验中，Claude + MHS 参与优化的 multi-dispense precision 预测约比厂家技术规格准确 12%，在高重复数据上约 17%；这是 Anthropic 实验结果，暂无独立评测。[Anthropic](https://www.anthropic.com/news/model-hardware-standard-research-preview)

### 4. ⭐ Google Gemini 3.8 Flash 内测：Flash 系列继续服务 coding 和 agent 高频 token 场景

- 背景：Google 近期持续快速迭代 Gemini Flash，DeepMind 新闻页仍显示 Gemini 3.7 Flash 为公开模型更新，媒体报道称 3.8 Flash 已进入内部测试。
- 问题：企业和开发者的 agent/coding 工作流对每 token 成本和低延迟高度敏感，旗舰模型能力并非唯一约束。
- 方法：公开细节不足；从 Flash 产品线推断，重点仍是轻量高吞吐模型，并优先嵌入内部 coding/agent 平台做反馈。
- 效果：报道仅称内部早期反馈有改进且发布未确认；没有公开技术报告或独立评测，应视为高价值但未落地信号。[Business Insider](https://www.businessinsider.com/google-employees-testing-next-gemini-flash-3-8-model-2026-8) / [Google DeepMind](https://deepmind.google/blog/)

### 5. ⭐ OpenAI Codex Persistent mode：长期运行 agent 的权限和任务续航问题浮出水面

- 背景：Codex 已从 coding agent 扩展到更通用的工作执行界面，长期任务和跨工具自动化需要 agent 能持续跟进。
- 问题：persistent agent 容易带来权限扩张、错误累积、无提示行动和安全审计问题；“主动性”必须和批准机制绑定。
- 方法：WIRED 报道的代码线索显示 Persistent mode 会包含 proactivity 指令，允许 agent 基于上下文生成后续任务，同时声明不扩大既有权限，涉及外部系统变更仍需用户批准。
- 效果：目前不是正式发布，也没有公开模型指标；价值在于显示 OpenAI 正在把 agent 从一次性任务转向持续工作流，暂无独立评测。[WIRED](https://www.wired.com/story/openai-is-developing-a-persistent-ai-agent/)
