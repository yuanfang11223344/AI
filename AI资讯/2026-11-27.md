## 🧠 大模型与 LLM 技术解读

### 🔥 GPT-6.2：专业工作模型与聊天模型的分层发布

- **背景：** 前沿模型正同时服务编码、研究和消费级对话，单一版本难以同时满足深推理、低延迟和产品安全需求。
- **问题：** 企业需在复杂任务能力、token 成本、工具调用兼容性与上线风险间取舍。
- **方法：** OpenAI 将 Astra 定位为高难度推理/编码，Sol 定位为更快、更高效的多步工作；API 通过 Responses 或 Chat Completions 提供，工具调用要求 Responses API。Chat 端另使用为对话调优的 GPT-6.2 Sol 版本。
- **效果：** OpenAI 的 Chat 测试声称图像理解、复杂指令遵循与内部 BrowseComp 均优于 GPT-6；这些是厂商内部评测，暂无覆盖真实企业任务的独立评测。
- **来源：** [API changelog](https://developers.openai.com/api/docs/changelog)｜[ChatGPT release notes](https://help.openai.com/en/articles/6825453-chatgpt-release-notes)

### ⭐ GPT-6.2 的安全阈值披露

- **背景：** 具备浏览、代码和工具调用能力的模型，风险不只来自文本输出，也来自可执行工作流。
- **问题：** 发布方需要说明模型能力何时达到更高的网络、生物或自我改进风险阈值，以及实际采用哪些保障措施。
- **方法：** OpenAI 的 system card 将 GPT-6.2（11 月 23 日 Chat 版本）置于其 Preparedness Framework 的 Cybersecurity “critical”与 Bio/Chemical、AI Self-Improvement “high”阈值，并说明部署了相应 safeguards。
- **效果：** 这是发布方的安全自评与部署声明，不能替代外部红队复核；对使用方的直接含义是需将权限、审计与人工审批纳入 Agent harness。
- **来源：** [GPT-6.2 System Card](https://deploymentsafety.openai.com/gpt-6-2-chatgpt/health)

### ⭐ Gemini Decisions API：把 Agent 路由变为闭集判定

- **背景：** Agent 系统中，大量工作是工具选择、策略检查、上下文分级等闭集决策，而非生成长文本。
- **问题：** 若每个判定都通过自回归生成完成，会增加延迟、输出 token 成本和不确定性。
- **方法：** Google 推出 Gemini Decision 1：对同一多模态输入和至多 1,000 个 yes/no、选择或 rubric 问题做单次 forward pass，返回概率与置信度。
- **效果：** Google 声称端到端延迟为 150–250 ms、输入价格为每百万 token 0.10 美元且无输出 token 计费；为官方指标，暂无独立压测。
- **来源：** [Google 官方公告](https://blog.google/innovation-and-ai/technology/developers-tools/gemini-decisions-api/)

### ⭐ Claude Fable 5.2 / Mythos 5.2：面向技术工作的能力声明

- **背景：** 实验室正在把通用对话模型扩展为代码、金融与科学的专业助手。
- **问题：** 专业任务同时要求长程规划、工具使用和可靠领域判断，单一排行榜无法替代端到端验证。
- **方法：** Anthropic 将 Fable 5.2 与 Mythos 5.2 作为其面向“daunting technical work”的最新模型对外发布，但新闻索引页未披露完整训练方法或可复现 benchmark 配置。
- **效果：** 目前能确认发布与定位；性能优势为厂商宣称，关键技术细节和独立评测仍不足。
- **来源：** [Anthropic Newsroom](https://www.anthropic.com/news)
