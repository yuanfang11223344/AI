## 🧠 大模型与 LLM 技术解读

### 🔥 GPT-6.2 Astra / Sol：专业工作与高效 Agent 的模型分层

- **背景：** 企业需要同时覆盖长程研究、编码和低成本多步任务。
- **问题：** 单一模型难以同时优化复杂任务质量、输出 token、时延与工具调用兼容性。
- **方法：** OpenAI 将 Astra 定位为高难推理/编码，Sol 定位为更快的日常工作模型；二者支持 Responses 与 Chat Completions，工具调用限定在 Responses API。
- **效果：** 官方称在专业工作、科学终端任务等评测上优于前代且输出 token 更少；属于厂商评测，暂无针对真实企业工作流的独立复现。
- **来源：** [发布公告](https://openai.com/index/introducing-gpt-6-2-astra-sol/)｜[API changelog](https://developers.openai.com/api/docs/changelog)

### ⭐ GPT-6.2 Chat：将模型能力与部署 safeguard 一并披露

- **背景：** 消费级 Chat 模型也可访问图像、浏览和复杂任务能力，风险不再只来自文本生成。
- **问题：** 能力升级后，使用者需知道哪些场景应触发更严格的权限、审计与人工审批。
- **方法：** OpenAI 在 system card 中按 Preparedness Framework 列出网络、生物/化学及 AI self-improvement 阈值，并描述相应 safeguards；Chat 端则采用为对话优化的版本。
- **效果：** 官方称复杂指令遵循、图像理解和内部 BrowseComp 优于 GPT-6；安全等级和效果均为发布方材料，暂无独立端到端审计。
- **来源：** [System Card](https://deploymentsafety.openai.com/gpt-6-2-chatgpt/avoiding-deceptive-interactions-with-users)｜[release notes](https://help.openai.com/en/articles/6825453-chatgpt-release-notes)

### ⭐ DART：从失败推理轨迹挖掘数学后训练数据

- **背景：** 数学推理后训练常依赖 verifier 通过的轨迹，但难题中这类轨迹稀缺。
- **问题：** 单纯独立采样会消耗大量生成预算而仍覆盖不足。
- **方法：** DART 对被拒轨迹按不确定性定位关键推理步，生成有意差异化的替代候选，再用参考答案引导完成轨迹。
- **效果：** 论文报告在 DeepMath-103K 上比等量 Monte Carlo 多恢复 37% 难题，并在若干数学评测取得更高点估计；仅为论文报告，需等待独立复现。
- **来源：** [arXiv:2611.34928](https://arxiv.org/abs/2611.34928)

### ⭐ Mixture-of-Loops Transformer：用 KV 跨循环复用换取 token efficiency

- **背景：** looped Transformer 能复用层，但循环计算会拖累推理效率。
- **问题：** 如何保留跨深度记忆，同时避免每次解码都完整循环。
- **方法：** MoLT 用 Mixture-of-Loops Attention 在循环间选择性复用 KV；U-MoLT 把 memory construction 和 prediction readout 分离，跳过未用 decoder traversal。
- **效果：** 作者报告在不同规模预训练中提高 validation token efficiency、并在小模型上接近非循环基线时延；实验规模与设置需由后续复现验证。
- **来源：** [arXiv:2611.34923](https://arxiv.org/abs/2611.34923)
