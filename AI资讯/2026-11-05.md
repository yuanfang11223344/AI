## 🧠 大模型与 LLM 技术解读

### 1. ⭐ LifeVal：从知识测验移向个人事务

- **背景**：浏览器、computer use 与 connectors 让模型开始承担跨应用任务。
- **问题**：传统 benchmark 的正确率和真实事务的可交付性之间存在缺口。
- **方法**：OpenAI 以时间使用调查和 3,995 人偏好调查构造日常事务任务分类。
- **效果**：官方给出部分任务表现，未提供可独立复算的统一总体结论；暂无独立评测。
- 来源：[原始来源](https://openai.com/index/lifeval/)

### 2. ⭐ Flide：为决策树做精确 state forking

- **背景**：搜索、规划、分类式 Agent 常有共享的 token 前缀。
- **问题**：重复跑相同前缀浪费 GPU；不精确缓存可能损害决策一致性。
- **方法**：论文以 token 流表达逻辑树，利用 ForkAttention 复用 attention 与 Gated DeltaNet 状态。
- **效果**：作者报告最高 9.5× 查询加速；仅是论文设定，暂无独立评测。
- 来源：[arXiv](https://arxiv.org/abs/2610.42148)

### 3. ⭐ DecisionRank：针对排序任务的 on-policy 蒸馏

- **背景**：RAG 的重排常受生成式 ID 解码成本影响。
- **问题**：教师输出序列、学生分数排序的学习目标错位。
- **方法**：先让学生分数形成排序，再获得条件化教师反馈，以 item-space on-policy distillation 训练。
- **效果**：作者报告在特定基准上优于其生成式对照的速度；应连同召回器、候选数和硬件审视，暂无独立评测。
- 来源：[arXiv](https://arxiv.org/abs/2610.42128)

### 4. ⭐ PersonaChatBench：把用户差异纳入评测变量

- **背景**：同一任务面对不同用户，满意度与需求约束可完全不同。
- **问题**：只用合作型单一用户会掩盖服务质量差异。
- **方法**：固定任务而配置私有 persona card，分别量化任务结果、显式需求满足及模拟器保真度。
- **效果**：论文比较 20 个模型、六个领域并发现两类指标不总一致；模拟用户不是实证用户研究，暂无独立评测。
- 来源：[arXiv](https://arxiv.org/abs/2610.42060)
