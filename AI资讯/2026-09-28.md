## 🧠 大模型与 LLM 技术解读

1. 🔥 **GPT-6 Sol/Luna：frontier family 的成本曲线下移。**
   - 背景：GPT-6 Astra 发布后，OpenAI 需要把更强 reasoning、tool use 与长上下文能力扩散到 Codex、ChatGPT Work 和 API 的高频任务。
   - 问题：企业落地瓶颈不是单一最高 benchmark，而是单位 token 成本、延迟、上下文缓存、工具调用稳定性和治理控制。
   - 方法：OpenAI 将 GPT-6 系列拆成 Sol/Luna 等生产档位，面向专业复杂任务和高频迭代任务，在 Responses / Chat Completions API 中继续提供 text/image input 与 text output。
   - 效果：官方称同档 API 价格较 GPT-5.6 系列下降 50%；这是官方披露，暂无独立系统评测。来源：[OpenAI](https://openai.com/index/introducing-gpt-6-sol-and-luna/)、[API changelog](https://developers.openai.com/api/docs/changelog)
2. 🔥 **Claude Opus 5.5：长程 agentic coding 的模型-接口联动。**
   - 背景：coding agent 已经从单轮代码生成转向跨文件、多工具、长时间执行与回放审计。
   - 问题：长程任务需要 1M context、稳定 tool use、更大输出窗口和成本可控的 thinking；否则 agent 会被上下文截断、输出上限和预算打断。
   - 方法：Anthropic 在 Opus 5.5 文档中列出 1M context、128K max output、adaptive thinking、thinking blocks、forced tool use 与 computer-use 相关行为。
   - 效果：Anthropic 称典型工作负载成本较 Opus 5 下降约 40%、输出速度提升超过 30%；暂无独立复现。来源：[Anthropic](https://www.anthropic.com/claude-opus-5-5)、[platform docs](https://platform.claude.com/docs/en/models/opus-5-5/overview)
3. 🔥 **Self-supervised confidence training：不直接惩罚长度，也可能减少 reasoning tokens。**
   - 背景：reasoning model 的推理链越长，线上成本和延迟越高；显式 early stopping 或长度惩罚可能伤害准确率。
   - 问题：如何在不引入外部标注和不直接优化短输出的情况下，让模型学会更高效地推理。
   - 方法：arXiv 新论文让模型用自监督方式预测中间推理状态的答案置信度，只用 600 个训练问题微调 Gemma、Qwen、Nemotron、GPT-OSS 等模型。
   - 效果：论文声称在数学、科学、代码 reasoning benchmark 上，同等准确率下生成 tokens 最多减少 25%；这是论文实验结果，暂无独立评测。来源：[arXiv:2609.31619](https://arxiv.org/abs/2609.31619)
4. ⭐ **Belief Self-Distillation：LLM 对用户意图的内部建模可读写。**
   - 背景：LLM 会根据对用户身份、意图和上下文的推断调整回答，安全拒答也可能依赖这种隐式用户模型。
   - 问题：这些“用户信念”如果不可观测，企业很难解释模型为什么拒答、放行或改变风格。
   - 方法：论文提出 BSD，让冻结 LLM 从自然对话中自蒸馏出紧凑用户表示，并测试该表示的解码与因果写入能力。
   - 效果：论文声称可恢复用户信念并影响拒答行为；结论应限定在实验模型与任务，暂无独立评测。来源：[arXiv:2609.31603](https://arxiv.org/abs/2609.31603)
5. ⭐ **READ for LoRA composition：adapter 组合从权重合并转向有方向的读写约束。**
   - 背景：LoRA 降低单任务微调成本，但多个 independently trained adapters 合并时常发生干扰。
   - 问题：如何把新技能接到已有技能上，同时减少旧技能被覆盖，并避免运行时 routing 成本。
   - 方法：论文提出 READ，将 adapter 改写到 balanced canonical form，并让新 skill 只能读取旧 skill 输入子空间、不能写入旧 skill 输出子空间。
   - 效果：论文称在多个 benchmark suite 和两类模型上超过同 adapter 条件下的强基线；仍需第三方复核。来源：[arXiv:2609.31600](https://arxiv.org/abs/2609.31600)
6. 📌 **Agent trace 与 documentation 研究共同指向：agent 可审计性不能只靠日志长度。**
   - 背景：企业 coding agent 依赖 trace、文档、检索上下文和执行日志来解释行为。
   - 问题：如果 trace 可被篡改，或者静态文档不能改善 issue resolution，那么“更多上下文”并不等于更可靠。
   - 方法：近期论文分别研究 agent trace tampering、compact documentation benchmark 与 roundtrip evaluation。
   - 效果：这些结果提示 agent 评测要加入 trace integrity、serving stack 和实际任务成功率；暂无统一独立 benchmark。来源：[arXiv:2609.30266](https://arxiv.org/abs/2609.30266)、[arXiv:2609.31587](https://arxiv.org/abs/2609.31587)
