## 🧠 大模型与 LLM 技术解读

1. 🔥 GPT-6 Sol / Luna：成本曲线下移
   - 背景：GPT-6 Astra 发布后，OpenAI 需要把高能力模型扩展到更高频的 Codex、ChatGPT Work 与 API 任务。
   - 问题：企业和个人 agent 工作流的瓶颈不只是模型能力，也包括每次迭代、长上下文和工具调用带来的 token 成本。
   - 方法：OpenAI 发布 `gpt-6-sol` 与 `gpt-6-luna`，支持文本/图像输入和文本输出，继续走 reasoning model 路线，并通过缓存与推理效率降低价格。
   - 效果：官方声称 API 价格相对 GPT-5.6 同档下降 50%，Sol 在 AutomationBench 中以 xhigh effort 达到 33.2% 且每任务 $0.27；但这是厂商自有/引用评测，暂无独立评测。[来源](https://openai.com/index/introducing-gpt-6-sol-and-luna/) / [changelog](https://developers.openai.com/api/docs/changelog)

2. 🔥 Claude Opus 5.5：长程 coding agent 与 adaptive thinking
   - 背景：Anthropic 在 Opus 5 后继续强化编码、电脑使用和知识工作场景，面向长时间运行的 agent。
   - 问题：长程代码迁移和多步骤 agent 容易受成本、上下文、工具调用错误、prompt injection 与不可逆操作风险限制。
   - 方法：Opus 5.5 提供 1M context、128K max output、adaptive thinking 常开、工具/系统消息行为变化，并在 Claude API、Bedrock、Google Cloud、Microsoft Foundry 等平台可用。
   - 效果：Anthropic 声称相对 Opus 5 典型工作负载成本降低 40%、输出速度提升超过 30%，Terminal-Bench 4.0、FrontierCode、CursorBench 等指标领先或更具成本效率；这些主要来自官方与早测数据，暂无完全独立复现。[来源](https://www.anthropic.com/claude-opus-5-5) / [平台文档](https://platform.claude.com/docs/en/models/opus-5-5/overview)

3. ⭐ Gemini 3.8 Flash / Live：多模态实时交互继续产品化
   - 背景：Google DeepMind 9 月密集列出 Gemini 3.8 Flash、Gemini 3.8 Live、Live Avatar、TTS 与 agentic video understanding。
   - 问题：多模态模型正在从离线问答走向实时语音、视频理解和可控创作，瓶颈在延迟、稳定性、上下文连续性与安全控制。
   - 方法：公开列表显示 Google 将 Flash、Live、Cyber、TTS 与视频理解拆成不同产品/模型入口，按任务形态分层而非只发布一个通用模型名。
   - 效果：官网新闻页确认 9 月模型线更新，但本次公开页面没有给出完整 benchmark 与第三方评测；暂无独立评测。[来源](https://deepmind.google/blog/)

4. ⭐ Claude Opus 5.5 API 迁移：模型能力升级同时改变接口假设
   - 背景：高能力 agent 模型越来越依赖 thinking blocks、工具调用和长上下文会话状态。
   - 问题：从 Opus 5 迁移到 Opus 5.5 时，应用可能假设“thinking 可关闭”“强制工具调用总能返回正常结果”或旧 computer-use 工具仍兼容。
   - 方法：Anthropic 文档明确列出 breaking changes：thinking 不能关闭、forced tool use 返回 error、thinking blocks 与模型/会话绑定，部分旧 computer-use 工具不再接受。
   - 效果：这降低了模型行为不一致的空间，但要求 agent 框架更新调用层与错误处理；这是官方平台说明，实际迁移成本需项目实测。[来源](https://platform.claude.com/docs/en/models/opus-5-5/overview)

5. ⭐ Agent 仿真评测：从静态测试集转向生产轨迹 replay
   - 背景：企业开始把 agent 放进真实工作流，传统预定义 test case 难覆盖工具环境、外部状态和异常分支。
   - 问题：agent 变更经常不是“答错一道题”，而是改变工具调用路径、造成隐藏失败或现实世界副作用。
   - 方法：Raindrop Simulations 声称重放真实生产流量和测试样例，模拟 agent 周围世界，并用异常检测衡量 proposed change 的行为变化。
   - 效果：公司称该能力来自与 Fortune 100 合作并将开放 early access；目前是公司发布材料，暂无独立评测。[来源](https://www.raindrop.ai/blog/series-a/)

6. 📌 LLM 评测可复现性继续成为研究主题
   - 背景：模型发布节奏加快，提示词结构、vendor 差异和评测脚本细节会显著影响结论。
   - 问题：如果评测结论无法复现，模型排名和采购决策会被 prompt artifact 放大。
   - 方法：arXiv 新稿《How Reproducible Are Evaluation Conclusions?》做 LLM-inferred prompt structure 的 self-audit；另有《Low-Cost Assays for Measuring Model Behavior Across Vendors and Releases》关注跨厂商行为测量。
   - 效果：这些论文提供评测方法讨论，但不等同于新模型能力突破；需阅读全文确认实验设置和局限。[来源](https://arxiv.org/abs/2609.30074) / [来源](https://arxiv.org/abs/2609.30012)
